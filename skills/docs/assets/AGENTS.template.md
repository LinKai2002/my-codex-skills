# 仓库协作与开发规则

本文件适用于在本仓库工作的所有 session。

## 1. 理解项目与接手任务

- 需要了解项目背景、已交付模块及使用接口时，查阅[项目总览]({{overview_path}})。
- 开始或恢复功能开发时，查阅[项目进展文档]({{progress_path}})中对应模块的条目，确认已完成项、未完成项、最近验证结果及下一步。
- 需要实现细节、运行方法或实验依据时，再进入对应模块目录查阅说明、代码和实验记录。

## 2. 控制修改范围

- 修改前检查工作区已有变更，区分用户或其他 session 的工作与本次任务的修改。
- 将修改限制在当前任务和所属模块内，保留无关改动。新功能按约定放在独立模块目录中。
- 用户要求分步审定时，按已认可的范围实施。涉及尚未确认的架构、公开接口或实验假设时，先说明影响，由用户决定。

## 3. 编码与验证

- 编写 Python 代码时遵循 PEP 8，使用 UTF-8 和四空格缩进。沿用已有领域术语及兼容性命名。
- 涉及公开数值接口时说明输入、输出、数组形状和单位。新增依赖时，在所属模块记录环境要求。
- 根据变更补充并运行针对性测试。数值算法使用小规模可验证算例或独立参考解对照，注明误差容限。交付时说明实际验证结果及未验证项。

## 4. 文档与实验维护

- 交付或变更可用功能时，更新项目总览中对应模块的功能点、使用接口、关键函数和关键数据结构。
- 开发状态发生变化时，按功能归属增量更新项目进展。完成项记录验收依据；未完成项记录当前进度、下一步和待定事项。
- 模块实现细节维护在模块目录中。实验保存在所属模块的实验目录下，每个实验使用能反映内容的独立目录，并记录目的、配置、运行方法和结果。
- 交接前核对文档与实际代码、测试和实验记录是否一致。

## 5. 逐文件汇报修改

- 每次交付或分步交付时，列全自上次汇报以来新增、修改、删除、移动或重命名的文件。每个文件写明：文件路径、修改位置、修改梗概。
- 修改位置优先用函数、类、配置项或文档章节标识；有助于定位时附行号。整文件新增或删除可标为“全文”；移动或重命名列出旧路径和新路径。
- 同一文件有多处独立修改时，每一处都要提到，每处用一句话概括即可。汇报前对照起始工作区状态、实际操作及最终差异，区分本轮修改与原有修改。
- 汇报也覆盖未跟踪文件、被忽略的实验产物及本轮创建后移除的临时文件。同用途文件可合并说明，但须列全路径。

## 6. 提交与评审

- 每次创建 Git 提交前，必须获得用户对本次提交的明确许可。未经许可，不得擅自 commit。
- 提交前检查本次变更涉及的文档是否已同步，并核对需要提交的文档是否包含在用户获准的暂存范围内。
- 提交前核对暂存范围，只纳入本次任务相关文件；缓存和临时输出不纳入提交。
- 提交说明使用简洁、具体的动词短语。已创建提交时，报告提交号、纳入的文件及仅保存在本地的相关产物。
- 涉及数值或性能变化的评审说明，应给出算例、运行环境、验证方法和实际结果。
